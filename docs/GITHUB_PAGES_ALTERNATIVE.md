# GitHub Pages: защо не става и каква би била алтернативата

## Кратко

**GitHub Pages не може да хоства Decorron.**

GitHub Pages е статичен хостинг. Той връща файлове такива, каквито са:

- не изпълнява PHP — значи Laravel не работи;
- не предоставя MySQL и не може да се свързва с база данни;
- няма сървърна сесия, CSRF проверка, нито автентикация.

Всичко, което прави Decorron надеждно — валидацията на входните данни, преизчисляването на цената на сървъра, snapshot-ите на историята, политиките за достъп — се случва в PHP. Публикуването на статичен export в GitHub Pages би дало страница, която **изглежда** като приложението, но не записва нищо и не може да бъде наречена работещо Laravel приложение.

**Хранилището в GitHub е за кода.** Самото приложение се пуска на PHP хостинг или VPS — вж. [`DEPLOYMENT.md`](DEPLOYMENT.md).

---

## Какво МОЖЕ да се сложи в GitHub Pages

- презентационна страница за продукта (статичен HTML);
- тази документация, публикувана като сайт;
- екранни снимки и ръководство за потребителя.

Тоест GitHub Pages е подходящ за *витрина*, не за самото приложение.

## Ако все пак искате изцяло статична версия

Възможно е да съществува **отделна** статична версия — самостоятелен продукт, който пази данните в браузъра (IndexedDB). Тя **не** замества Laravel приложението и има съществени ограничения.

> Тази версия **не е изградена** в хранилището. Разделът описва какво би трябвало да се промени, ако някой реши да я направи.

### Какво трябва да се промени

| Слой | В Laravel версията | В статична версия |
| --- | --- | --- |
| Съхранение | MySQL + Eloquent | IndexedDB (напр. `dexie`) |
| Маршрутизиране | Laravel + Inertia | React Router с hash маршрути (`/#/calculations`) |
| Валидация | Form Requests (сървър) | само клиентска, напр. `zod` |
| Финансови изчисления | `PricingCalculator` (PHP, `brick/math`) | пренесени в TypeScript върху `big.js` |
| Автентикация | Laravel сесии и политики | няма — защитата е физическият достъп до устройството |
| Данъчни ставки | `config/pricing.php`, недостъпни от UI | константа в JS бъндъла, видима за всеки |
| Пагинация и търсене | SQL заявки | обхождане на IndexedDB в браузъра |
| Експорт | изглед за печат от сървъра | същото, но от клиента |

### Стъпки накратко

1. Нов Vite + React проект (или отделна входна точка в същото хранилище).
2. Пренасяне на `resources/js/lib/pricing.ts` и `resources/js/lib/money.ts` — те вече са чист TypeScript и работят без сървър.
3. Схема в IndexedDB за `units`, `materials`, `calculations`, `calculation_items` със същите полета и същата snapshot логика.
4. Повторно използване на React страниците, като Inertia заявките се заменят с локални заявки към IndexedDB.
5. Базов път на билда, съответстващ на името на хранилището:
   ```js
   export default defineConfig({ base: '/decorron/' })
   ```
6. GitHub Actions workflow, който изгражда и публикува `dist/` в GitHub Pages.
7. Експорт/импорт на JSON, за да може потребителят сам да си пази данните.

### Ограничения, които остават

- **Данните живеят само в този браузър.** Друг телефон, друг браузър или изчистване на данните на сайта = празно приложение.
- **Няма сигурна защита.** Всеки с достъп до устройството вижда всичко; данъчните ставки са във видим JS код.
- **Няма синхронизация** между устройства и няма споделяне между потребители.
- **Няма сървърна проверка** на изчисленията — доверие само в клиентския код.
- Браузърът може да изчисти IndexedDB при недостиг на място.

## По-подходящи алтернативи на GitHub Pages

Ако целта е безплатен или евтин хостинг на **истинското** приложение:

| Вариант | Бележка |
| --- | --- |
| VPS (Hetzner, DigitalOcean, Contabo) | пълен контрол; вж. `DEPLOYMENT.md` |
| Български споделен хостинг с PHP 8.2+ и MySQL | най-евтино за едно приложение |
| Laravel Forge / Ploi + VPS | автоматизиран deployment |
| Laravel Cloud / Fly.io / Railway | управляван PHP хостинг с база данни |

Всички те изпълняват PHP и предоставят MySQL — тоест Decorron работи без промени в кода.
